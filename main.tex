\section*{Motivation and Problem}
Quantum computers can solve certain problems asymptotically faster than any known classical method: Shor's algorithm factors integers in polynomial time, whereas no polynomial-time classical algorithm is known~\cite{shor}. Unlike the reliable-gate abstraction of classical computing, physical quantum operations remain error-prone: entangling-gate infidelities near $10^{-3}$ state-of-the-art platforms have only recently reached, while many applications target logical error rates below $10^{-10}$~\cite{googleqec}. \textbf{Quantum error correction (QEC)} addresses this gap by encoding logical information across multiple physical qubits. A \emph{QEC code} encodes logical information redundantly and defines parity checks whose measurements detect errors without disturbing the encoded state.

Discovering good codes requires trading off logical error rate, qubit overhead, and hardware constraints. Experts construct algebraic code families, while heuristic and reinforcement-learning methods explore candidate codes and encoding circuits~\cite{olle}. We ask: \textbf{how should an AI system allocate reasoning, communication, and evaluation resources as evidence about a candidate changes?} Algebraic checks are expensive and exact, distance computation is exact but expensive and circuit-level noise simulation yield costly statistical estimate. Fixed agent workflows cannot adapt this allocation.

\section*{Proposed Innovation: Adaptive Dual-Loop Discovery}
We propose \textbf{AgentQEC}, a multi-agent framework coupling a \textbf{fast loop for candidate generation and screening} with a \textbf{slow loop for circuit-level evaluation}. Our focus is to use costly evaluation feedback both to guide subsequent code construction and to improve inexpensive candidate screening.

\textbf{Fast loop: generation and screening.} Designer and critic agents iteratively propose and refine code-construction programs. Executable tools check algebraic validity and resource constraints, extract inexpensive structural features, and return violations for repair. A lightweight learned screening model uses these features and the specified evaluation settings to predict circuit-level performance and uncertainty. A budget-aware allocator selects a subset of valid candidates for the slow loop, balancing predicted quality with exploration rather than relying solely on fixed code-level scores.

\textbf{Slow loop: evaluation and feedback.} Selected codes are compiled into syndrome-extraction circuits under the target hardware constraints, then evaluated through noisy sampling and decoding to estimate logical error rates (LERs) and their statistical uncertainty. The results support \textbf{two feedback paths}: structured records of constructions, implementation costs, and performance estimates guide the agents' next proposals; the same observations update the screening model to improve subsequent candidate ranking. Algebraic checks remain independent of learned predictions, and final candidate quality is assessed through circuit-level evaluation, not screening scores. By improving both \emph{what to generate} and \emph{what to evaluate}, AgentQEC aims to reduce end-to-end discovery cost at a target QEC quality, accounting for inference, tool execution, and model-update overhead.

\section*{Agentic System Efficiency and QEC Quality}
\textbf{Agentic system efficiency} targets avoidable inference, inter-agent communication, and synchronization overhead. The controller selectively activates specialists and budgets their context exchange. Shared structured records reuse tool results only when candidate, noise, and decoder settings match; dependency-aware scheduling overlaps independent checks and reasoning. We will measure latency, GPU time, peak memory, tokens, communication volume, and tool time, including coordination overhead; training costs will be reported separately. \textbf{QEC system efficiency} is evaluated through logical-error rate at fixed noise and decoder settings, physical-qubit overhead, syndrome-extraction depth, and decoder latency. We will compare agent cost at matched QEC quality and QEC quality at matched budgets, rather than assume simultaneous gains in both.

\section*{One-Year Scope and Evaluation}
Year one will deliver a CSS-code prototype, learned controller, and reproducible benchmark. On held-out noise settings and code sizes, we will compare fixed, rule-based, and learned coordination using the same specialist/tool pool, alongside single-agent and heuristic/RL code-search baselines. Ablations will isolate feedback, routing, and shared-state scheduling to quantify the quality--compute tradeoff.
